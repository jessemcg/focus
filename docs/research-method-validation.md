# Fixed neutral research method — validation

Implemented on **Work**, 2026-10-13, from Focus baseline `a8e80fb`. Current method:
`focus-record-qa` version 1. All execution stayed on the session computer, in
independent disposable source copies and locked environments selected through the
absolute UvEnvironments helper. HOME/XDG/FOCUS_CONFIG_DIR and metrics locations were
isolated. Records, profile sentinels, saved answers and agents were synthetic/offline.
No paid/live-model call, remote-computer access or private data migration occurred.

  fallback capture**, preserving prior artifact bytes. Follow-up controller tests

## Hamburger-menu regression follow-up

The profile-menu installer had also attached the ordinary menu model. Removing that
installer left the header hamburger button disconnected. Restored the explicit
`set_menu_model` connection in `app.py` without restoring any profile UI.

The GTK harness now opens the actual hamburger popover, checks its ordinary entries,
activates **Settings** through the rendered menu item and verifies that the Settings
window is visible. `tests/test_application_menu.py` runs this isolated synthetic
acceptance as part of pytest (requires a local display). It failed before the fix
with `Hamburger menu model is unattached` and passed afterward. Native Computer Use
also confirmed the menu opens on a pointer click in the owned synthetic window.
The rerun full suite passed **670 tests + 11 subtests, no skips**, with the same two
existing deprecation warnings. No real preferences/case files or model calls.

## Limits and adoption

Deterministic/offline acceptance is **not live-model comparative answer-quality
validation**. Loss of specialty shortcuts is mitigated by record-derived vocabulary,
generic contemporaneous-evidence instructions and invariant retrieval fixtures, not
hidden profiles. Live-model quality testing requires separate authorization.

Restart Focus and explicitly ask a new question to use the fixed method, even for
previously profile-bound bundles. No confirmation dialog, migration flag, private
cleanup or RecordPrep regeneration. Old saved answers retain historical metadata.
Older Focus releases may not read new schema-3 answers; never auto-down-convert them.
